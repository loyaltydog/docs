Merchant product routes use **bearer token authentication**:

```http
Authorization: Bearer <secret>
```

Two gift-card **balance-check** routes are public and take no `Authorization` header: `POST /v2/giftcards/customer/balance-check` and `POST /v2/giftcards/programs/{programId}/balance-check`. Everything else in the public schema requires a Bearer secret.

Production base URL: `https://api.loyalty.dog`. Public product routes are under **`/v2`**.

The machine-readable public schema is [`openapi.public.json`](/openapi.public.json) (SWE-1133). `/openapi.json` is the **full** app schema (login, MFA, API Keys, signup) and is not the public product.

## Two credential kinds

| Kind | Shape | How you get it | Limits / freeze |
| --- | --- | --- | --- |
| JWT App Key | `eyJ…` three-part JWT | Dashboard [API Keys](https://app.loyalty.dog/account/appkeys). `POST /appkeys` still mints this. | Today's 401/403/429 bodies. **Not** in the hashed-key limiter. **Never** frozen for API Access cancel. |
| Hashed public key | `ld_test_…` / `ld_live_…` | **Not self-serve.** Do not POST `/appkeys` expecting `ld_*`. | Envelope errors. Per-key 429 + monthly quota. Frozen with 402 `api_subscription_inactive` if API Access is canceled. |

There is no public issuance API. Dashboard create/rotate/revoke are not on the public OpenAPI.

Merchants subscribe to **API Access** from the same [API Keys](https://app.loyalty.dog/account/appkeys) page (Stripe Checkout / Customer Portal). That plan **does not change JWT or `legacyToken` behavior**. Freeze and metering apply only to hashed `ld_*` keys.

<Warning>
  Changing a JWT App Key or opaque `legacyToken` 401/403/429 body is a regression (SWE-1181). Hashed `ld_*` keys use a separate envelope.
</Warning>

## Scopes (`ld_*` only)

JWT App Keys have implicit merchant access. A hashed key is least-privilege (default: no scopes). Typical public reads need `loyalty:read`. Gift-card redeem needs `giftcards:redeem` — `fullAccess` on a public key does **not** grant it.

Missing scope → **403** with `code: forbidden` naming the missing scope.

## Identity ping

`GET /v2/token` with a valid Bearer returns the caller. Unscoped `ld_*` keys can ping identity; product routes still need scopes.

## Rotating tokens

Treat tokens like passwords.

1. Create a new API Key in the dashboard.
2. Deploy the new secret to your services.
3. Revoke the old key.

<Tip>
  Use a secrets manager — AWS Secrets Manager, GCP Secret Manager, HashiCorp Vault, Infisical, or your platform's equivalent — and never bake tokens into images or commit them.
</Tip>

## Common errors

| Status | Meaning | Fix |
| --- | --- | --- |
| `401` | Missing or invalid token | Check the `Authorization` header |
| `403` | Missing scope or IP allowlist miss | See [Errors](/guides/errors) |
| `402` | API Access canceled (`ld_*` only) | Resume the subscription |
| `429` | Rate-limited | Honor `Retry-After`. See [Rate limits](/guides/rate-limits) |
