---
title: "Rate limits"
description: "Per-key burst, sustained, and monthly limits for the LoyaltyDog public API."
---

Hashed public keys (`ld_live_…` / `ld_test_…`) are rate-limited **per key**, not per IP. API keys (JWTs) and legacy opaque tokens are not subject to this limiter — they keep today's behavior.

## Limits

| Window | Default | 429 `code` |
| ------ | ------- | ---------- |
| Burst | 60 requests / 60 seconds | `rate_limited` |
| Sustained | 1,000 requests / 3,600 seconds | `rate_limited` |
| Monthly | 10,000 requests / UTC calendar month | `monthly_quota_exceeded` |

## Response headers

Every hashed-key response carries:

- `X-RateLimit-Limit`
- `X-RateLimit-Remaining`
- `X-RateLimit-Reset`

`Retry-After` is present on 429 responses only, and `X-RateLimit-Remaining` is always `0` on a 429.

<Warning>
  Don't infer how long to wait from `X-RateLimit-Limit` alone — a sustained-window 429 still advertises the burst cap on that header. Always use `Retry-After`.
</Warning>

## Monthly quota

Hitting the monthly cap returns a hard 429 (`monthly_quota_exceeded`) until the UTC month rolls over. There is no overage billing today — usage-based billing is a later milestone.
